# Generated identity controller — FORMA-0179

This source is selected only by the authenticated password+mandatory-TOTP profile. Public generated children use fixed no-auth selector assets. `identity-client.jsx` exports `IdentityProvider`, `useIdentity`, `IdentityControls` and `AuthPage`; view source is physically vendored to adjacent `presentation/`. There is no private runtime Forma dependency.

The Node descriptor `GET /api/identity` owns `signed-out`, `enroll`, `challenge`, `authenticated` and `forbidden` stages. Local view choices select forms; they grant neither session nor role nor MFA assurance. The workspace remains guarded by server page checks and per-request Python authorization. Enrollment flags never substitute for session-bound assurance. Unknown descriptors/network failure fail closed with localized generic text.

The controller calls maintained same-origin endpoints with maintained cookies: signup/email, sign-in/email or username, send-verification-email, request/reset-password, two-factor enable/verify-totp/verify-backup-code and sign-out. JSON includes only endpoint-required fields, never caller-selected identity, role, organization, `trustDevice` or MFA-complete flags. Every mutation refreshes the server descriptor. There is no automatic credential/code retry after errors; an ambiguous factor response refreshes session state and lets the person decide the next action. No provider action is configured.

Reset URL tokens are read into transient React state and removed from the current browser address via replaceState; the runtime must separately suppress token-bearing initial request/access logs. Local QR generation uses the ordinary pinned qrcode dependency, never an external QR service; a manual key remains available. Enrollment URI/recovery codes exist only in transient state and DOM intended for the person enrolling. They clear on stage transition and after successful factor submission. They must never enter browser storage, analytics, logs, exported artifacts or screenshots. Mail request acceptance says only “Check your inbox if eligible”; it proves neither queueing nor delivery. No public mail/test-login bypass exists.

Accessible English form labels: `Create account` uses Name/Username/Email/Password; `Sign in` uses Email or username/Password; `Set up two-factor authentication` uses Current password; `Confirm authenticator setup` uses Authentication code; `Two-factor challenge` uses Authentication code and `Use a recovery code`; recovery uses Recovery code; password reset uses Email then New password. Native action `Continue` submits; `Request verification` resends to the transient signup email; `Sign out` calls the maintained endpoint. The form registry remains fully replaceable and parent-scoped styles/tokens remain inherited.

Actual generated-app verification belongs to the lead's isolated packed-consumer PostgreSQL/mail-capture/browser integration tests. Component tests alone do not establish real sign-in/MFA, delivery, production hosting, recovery operations or production readiness. Never capture enrollment secrets in persistent browser artifacts.

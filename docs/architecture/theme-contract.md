# Semantic parent theme contract — FORMA-0177

`app.config.json.theme` is the actual parent theme input for the generated child. The child receives `frontend/src/theme.js`, `theme-tokens.json`, styles, components and all other required source. No Forma service, seller checkout or private runtime package supplies styling. This is a bounded semantic styling contract, not a claim that a finite JSON object can express every possible design.

## Validation and source authority

`frontend/src/theme-tokens.json` declares every supported token, default, allowed scalar type/range and CSS unit. The generator's `schemas/app-config.schema.json` contains the same token property definitions; a config test checks exact equality. Unknown tokens, additional theme properties, unsupported presets, missing token objects, malformed colors/fonts, non-finite numbers, invalid numeric types and out-of-range values fail before generation. Runtime `themeStyle` independently enforces the same shipped registry before the root layout emits any CSS variables. Editing a generated config cannot silently inject an unsupported style or fall back after a rejected value. The registry is ordinary app-owned source, not downloaded executable configuration.

Presets `linen` and `midnight` merge registry defaults with their existing color/radius overrides. Parent `tokens` override the preset. `themeStyle` emits `--app-<token>` variables with registry-controlled units; color inputs are six-digit hex, numeric inputs never contain arbitrary CSS. Font lists support plain or single-quoted family names, safe comma lists and standalone `inherit`; URL/font loading is not part of this config. Fonts must already exist or be loaded explicitly by app source. No remote font, stylesheet or network request is introduced.

## Supported semantic controls

- Colors: accent/onAccent, page background, surface, text/muted/border, soft content surface, sidebar/sidebarText, highlight, error/success/warning/info and focus. Navigation hover/active colors have bounded opacity; dialog overlay color/opacity are explicit. Warning/info are available for future app-owned status UI; their presence does not manufacture a new workflow.
- Typography: body `fontFamily`/`bodyFontSize`/`bodyLineHeight`; `headingFontFamily`/`headingScale`/`headingLineHeight`; `controlFontFamily`/`controlFontSize`/`buttonFontSize`; secondary-role `typeScale`. Native buttons, inputs, textarea and selects use parent control typography. The default `controlFontFamily: 'inherit'` follows the parent's body family. Existing secondary text sizes and heading roles remain proportionally controlled by typeScale; their distinct ratios remain source-owned.
- Shape/density: surface radius, controlRadius, navRadius, spacingScale, pagePadding, mobilePagePadding, panelPadding and controlPaddingX/Y. Numeric ranges preserve a useful bounded starter layout; they are not an arbitrary CSS escape hatch. Explicit semantic padding overrides take precedence over the proportional source spacing scale.
- Interaction: focus color/width/offset and motionDuration. Existing reduced-motion rules disable transitions/animations regardless of configured duration. RTL active navigation edge is logical; wrapping/geometry checks remain in the separate presentation stress proof.

Base defaults preserve the existing typography families, proportions and structure. Color-mixed navigation/overlay opacity reproduces the previous translucent treatments through named parent variables. Explicit semantic padding and control radius controls may refine those individual defaults; they are covered by actual theme/layout regression review rather than a pixel-identical promise.

The optional identity presentation reads the same parent semantic variables for fonts, heading scale, control sizes/radii/padding, panel spacing, focus, colors and surface shape. Its stylesheet selectors remain scoped to `.forma-identity`. It is still not selected/enabled by the public generator; themed auth screenshots demonstrate only controlled callback views, never real sign-in/MFA/provider operation.

## Structural source replacement remains necessary

Grid tracks, sidebar width, breakpoints, exact responsive composition, artwork/icons, letter spacing, local content hierarchy and some role-specific line-height/size ratios remain structural constants in app-owned source. Parent tokens cannot turn a sidebar into an unrelated composition or replace form DOM. Use the delivered component registry and replace entire Shell/AuthLayout/AuthField/AuthButton components when a customer's design needs different structure; preserve callbacks, labels, focus, validation and server authority. This distinction is intentional. The original unrestricted customization ambition is not satisfied solely by a fixed token catalog: the delivered source and complete component replacement contract are the escape path, with app-specific design acceptance still required.

## Actual verification and limitations

`node --test packages/config/test/config.test.mjs` checks registry/schema equality, all token value/type rejection, generator validation and runtime validation. Browser helper `node tests/blueprint-consumers/run-theme-contract.mjs` physically copies source into its own temporary Next consumer, installs its own lock-pinned dependencies, and applies two substantially different **actual root app.config.json** themes. It checks body/heading/native control typography, record and optional identity input radii, focus width, semantic spacing, desktop/mobile overflow and screenshots. The fixture uses controlled callbacks; it neither saves customer data nor calls a default API. It does not enable authentication or contact providers.

Evidence lives under ignored `.run/neutral-consumer/theme-contract-report.json` and `theme-parent-{1,2}-{desktop,mobile}.png`. The broader six default theme/layout regression and RTL/long-label geometry proofs remain separate integration evidence. Tests do not certify arbitrary color contrast, font availability, every token combination, screen-reader behavior or full WCAG. Consumers must review their actual theme and complete replacement components. Config/schema support does not publish an npm release or change the public starter's auth capabilities.
